# Инструкция для планировщика (нейросеть на ПК2)

Этот документ — для нейросети-планировщика (например, GPT), которая ведёт проект через GitHub, и для человека, который её настраивает.
Исполнитель — JustAI на ПК1: он берёт задачи из issues, пишет код, запускает проверки и тесты, отвечает в issues.
Как настроить сам мост — [github-bridge.md](github-bridge.md).

Есть два способа работать планировщиком:

- **A. JustAI на ПК2, профиль Architect.** Все действия ниже — инструменты (`github_create_task`, `github_merge_task` и др.). Инструкции уже встроены в профиль; раздел 3 ниже — справка.
- **B. Любая нейросеть с доступом к GitHub** (веб-чат с GitHub-интеграцией, свой скрипт). Всё делается текстом issues и комментариев. Скопируйте ей промпт из раздела 2.

## 1. Как устроена работа

```
план → задачи (issues) → ПК1 делает → отчёт + PR → планировщик проверяет → правки или слияние → следующие задачи
```

| Что нужно | Как сказать JustAI | Где ответ |
|---|---|---|
| Новая задача | issue с меткой `justai` или `[justai]` в начале заголовка | ход работы и отчёт в этом issue, PR |
| Задача после других | строка `Depends on #3, #4` в описании | начнётся, когда #3 и #4 слиты |
| Правки | комментарий в issue задачи (или issue: `/justai #N` + текст) | новый отчёт в issue задачи |
| Остановить | комментарий `/justai stop` (или issue `/justai stop #N`) | «остановлен», метка `justai:paused` |
| Продолжить | любой комментарий с указаниями (или issue `/justai continue #N`) | продолжает в той же сессии |
| Проверить, что работает | issue `[justai-test] …` со строкой `/justai test #N` | PASS/FAIL, отчёт по шагам, скриншоты |
| Выполнить команду | комментарий `/justai run npm test` (или issue: первая строка `/justai run #N npm test`) | код выхода и вывод |
| Принять и слить | комментарий `/justai merge` (или issue `/justai merge #N`) | «слит в main» или причина отказа |
| Закрыть ненужные issues | issue со строкой `/justai close #2 #3 #10` | «закрыты #2, #3, #10» |

Метки состояния: `justai:working` — делается, `justai:review` — готов PR (у проверки — PASS), `justai:failed` — не вышло (у проверки — FAIL), `justai:paused` — остановлено, `justai:merged` — слито.

Все команды пишутся **отдельной строкой**. ПК1 проверяет GitHub раз в минуту — ответ приходит не мгновенно; задачи выполняются по одной.

## 2. Промпт для нейросети-планировщика (вариант B)

Скопируйте целиком, заменив `ВЛАДЕЛЕЦ/РЕПОЗИТОРИЙ`.

```
Ты — ведущий разработчик и планировщик проекта в репозитории ВЛАДЕЛЕЦ/РЕПОЗИТОРИЙ.
Сам ты код не пишешь. Код пишет и запускает агент JustAI на другом компьютере: он берёт задачи из GitHub issues,
делает каждую в отдельной ветке, открывает pull request и отвечает в issue. Ты общаешься с ним только через issues.

ПРАВИЛА ЗАДАЧ
1. Начни с плана: разбей цель на маленькие задачи, каждая — на 15–60 минут работы и одну проверяемую цель.
2. Каждая задача — отдельный issue. Заголовок начинается с «[justai]». В описании:
   - Цель (1–2 предложения).
   - Требования — нумерованный список, конкретно: имена файлов, функций, тексты, цвета, поведение.
   - Готово, когда — как проверить: команда (например, «npm test проходит»), что видно на странице.
   - Не делать — чего не трогать.
   Агент — небольшая модель без памяти о других задачах: всё нужное пиши в саму задачу, не ссылайся на «как обсуждали».
3. Можно выложить весь план сразу. Если задача опирается на другие, добавь последней строкой
   «Depends on #N» (через запятую, если несколько). Она начнётся только после слияния этих задач.
4. Не ставь две задачи, меняющие одни и те же файлы, без зависимости между ними — будут конфликты.

ПРОВЕРКА РЕЗУЛЬТАТА
5. JustAI пишет в issue: комментарий «работает над задачей» (обновляется каждые ~30 с: план, последние действия, ошибки),
   затем итоговый отчёт: ветка, ссылка на PR, блок «Проверки проекта» и отчёт агента.
   «Проверки проекта» запускает сам JustAI — этому блоку верь больше, чем словам агента.
6. Прочитай изменения в pull request. Проверь: требования выполнены, ничего лишнего не сломано.
7. Для интерфейса проверь поведение, а не только код: создай issue
   «[justai-test] Проверка #N: что проверяем» с шагами и ожидаемым результатом
   (что открыть, куда нажать, что должно появиться, размеры экрана, например 1280 и 375),
   последней строкой «/justai test #N». Ответ — PASS или FAIL, отчёт по шагам и скриншоты. Проверка ничего не меняет.
8. Быстрая команда без задачи: комментарий в issue задачи «/justai run npm test» — придут код выхода и вывод.
   Если не можешь комментировать — issue, первая строка «/justai run #N npm test».

ПРАВКИ И ОСТАНОВКА
9. Если что-то не так — комментарий в issue задачи с конкретными правками (что, где, как должно быть).
   Если не можешь комментировать — issue со строкой «/justai #N» и текстом правок ниже.
10. Если в комментарии «работает над задачей» видишь, что агент застрял (одна и та же ошибка повторяется),
    напиши «/justai stop» (или issue «/justai stop #N»). Сделанное сохранится. Продолжить — комментарий с указаниями.
    Устаревшие или лишние issues закрывай issue со строкой «/justai close #2 #3 #10».

СЛИЯНИЕ
11. Когда задача сделана, проверки зелёные, а для интерфейса проверка дала PASS — комментарий «/justai merge»
    (или issue «/justai merge #N»). JustAI ещё раз запустит проверки и сольёт PR в основную ветку; issue закроется,
    задачи с «Depends on #N» начнутся сами.
12. Если ответ «конфликт» — комментарий: «влей основную ветку в эту ветку и разреши конфликты», затем снова «/justai merge».
    Если «проверки не прошли» — попроси исправить, затем снова «/justai merge».

ОТЧЁТ ЧЕЛОВЕКУ
13. После каждого шага коротко пиши человеку: какие задачи поставлены, что в работе, что слито, что застряло и почему.
    Не выдумывай результаты: опирайся только на ответы JustAI в issues.
```

### Пример задачи

```
Заголовок: [justai] Страница «Контакты»

Цель: добавить страницу контактов, доступную из меню.

Требования:
1. Файл contacts.html в стиле index.html (тот же <header> и css/style.css).
2. На странице: заголовок «Контакты», e-mail info@example.com ссылкой mailto, форма (имя, сообщение, кнопка «Отправить»).
3. В меню всех страниц — пункт «Контакты» после «О нас».
4. Форма пока ничего не отправляет: по нажатию показывает «Спасибо!» под кнопкой (js/contacts.js).

Готово, когда: страница открывается из меню, после нажатия кнопки видно «Спасибо!», в консоли нет ошибок.

Не делать: не менять остальные страницы, кроме пункта меню.

Depends on #12
```

### Пример проверки

```
Заголовок: [justai-test] Проверка #13: страница «Контакты»

1. Запусти сайт и открой главную.
2. Нажми «Контакты» в меню — должна открыться страница с заголовком «Контакты».
3. Заполни имя и сообщение, нажми «Отправить» — под кнопкой должно появиться «Спасибо!».
4. В консоли браузера не должно быть ошибок.
5. Скриншоты страницы «Контакты» на ширине 1280 и 375.

/justai test #13
```

### Как писать задачи для небольшой локальной модели (проверено на практике)

Исполнитель на ПК1 — модель ~8B. Она надёжно делает «запиши файл с этим содержимым» и плохо — «найди и поправь кусок».
В реальном прогоне одна задача с точечными правками заняла 11 запусков, а та же работа, поставленная полными файлами, — 3 минуты.

1. **Файл до ~400 строк — давай целиком.** «Замени всё содержимое `css/style.css` на текст ниже» + полный текст. Это самый надёжный формат.
2. **Одна правка — один файл, один блок.** Несколько правок в разных файлах — несколько комментариев по очереди (или файлы целиком).
3. **Не пиши «замени `display: flex` на `display: none`»**, если такая строка в файле не одна: процитируй правило целиком, с селектором и всеми строками, чтобы фрагмент был единственным.
4. **«Добавь в конец файла» пиши именно так** — у JustAI для этого отдельный режим (append), остальной файл не трогается.
5. **Проверяй результатом, а не отчётом.** В итоговом отчёте есть блок «Изменения в ветке» (по git) и «Проверки проекта» — смотри их. Точечно: `/justai run git grep -c "is-stub" -- css/style.css`, `/justai run node -e "…"`.
6. **Не повторяй уже сделанную правку** — сначала проверь файл (`/justai run git show HEAD:css/style.css` или дифф PR). Повтор JustAI отклонит, но это лишний круг.
7. **Больше 3–4 кругов правок по одной задаче — начни заново:** новая задача с полным содержимым нужных файлов вместо очередной правки. Длинная история путает маленькую модель.
8. **Застрял (одна и та же ошибка в ходе работы)** — `/justai stop` и переформулируй: целый файл или меньший шаг.
9. **Новые возможности — новыми файлами.** Создать новый файл модель делает надёжнее, чем переписать существующий. Если правку существующего не избежать — давай файл целиком и прямо пиши «запиши инструментом write_file».
10. **Задача-проверка: коротко и с точными селекторами.** 3–5 шагов, у каждого — CSS-селектор (`.mode-card[data-mode="hero"]`, `#btn-back`) и ожидаемый текст. PASS без строки `RESULT: PASS`, без действий или без скриншотов JustAI не засчитывает — смотри в отчёте «Действий агента / скриншотов». Логику надёжнее проверять командой (`/justai run node test.js`) или своими тестами, а проверку браузером оставлять для внешнего вида.
11. **После `write_file` в JS проверь синтаксис и запуск**, а не только `node --check`: модель может потерять `;` в конце строки перед `(function …)` — файл синтаксически верен, но падает при запуске.

## 3. Инструменты профиля Architect (вариант A)

| Инструмент | Что делает |
|---|---|
| `github_create_task(title, body, depends_on?)` | задача; `depends_on` — номера задач, после слияния которых она начнётся |
| `github_list_tasks()` | открытые задачи и их состояние |
| `github_review_task(issue)` | последний отчёт, результаты команд и дифф PR |
| `github_request_changes(issue, comment)` | правки комментарием |
| `github_test_task(title, steps, of_task?)` | проверка в браузере со скриншотами |
| `github_run_command(command, task?)` | одна команда в ветке задачи |
| `github_merge_task(issue)` | принять: проверки заново и слияние |

## 4. Чего JustAI не сделает (и это нормально)

- Не выполнит разрушительные команды без человека (`git push --force`, `rm -rf`, реестр, выключение) — обойдёт или напишет в отчёте.
- Не сольёт PR, если проверки красные, если задача не в состоянии «готов PR» или если на ПК1 выключено `JUSTAI_GITHUB_MERGE`.
- Не возьмёт задачи от чужих аккаунтов и из публичного репозитория (без явного разрешения).
- Не начнёт задачу, пока в папке проекта на ПК1 есть незакоммиченные изменения человека.
