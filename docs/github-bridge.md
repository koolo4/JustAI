# Мост через GitHub: планировщик на одном ПК, разработка на другом

Схема:

```
ПК2 (планировщик, сильная модель, например GPT по API)        ПК1 (исполнитель, Ollama, вся разработка)
JustAI, профиль «Architect»                                     JustAI, «Брать задачи из GitHub» = on
   │ github_create_task → issue с меткой justai                    │ раз в минуту: новые issues с меткой justai
   │                                                               │ ветка justai/issue-N → агент делает задачу
   │ github_review_task ← отчёт + дифф PR                          │ коммит, push, pull request «Closes #N», отчёт в issue
   │ github_request_changes → комментарий в issue                  │ новый комментарий → доработка той же ветки
   ▼                                                               ▼
                      приватный репозиторий на GitHub
```

Вы в любой момент видите всё на GitHub: задачи (issues), работу (ветки и pull requests), отчёты (комментарии). Слияние в основную ветку — ваше решение.

## 1. Репозиторий и токен (один раз)

1. Создайте на GitHub **приватный** репозиторий (с публичным мост не работает: задачи в нём мог бы написать кто угодно).
2. Создайте **fine-grained токен**: GitHub → Settings → Developer settings → Fine-grained tokens → Generate.
   - Repository access: только этот репозиторий.
   - Permissions: **Contents**, **Issues**, **Pull requests** — Read and write (Contents нужен и для скриншотов в отчётах).
3. Создайте в репозитории метку `justai` (Issues → Labels) — или её создаст первая задача.
4. Рекомендуется: Settings → Branches → защитить `main` (запрет прямого push). JustAI пишет только в ветки `justai/issue-N`.

## 2. ПК1 — исполнитель (этот ПК, Ollama)

1. Склонируйте репозиторий (например, через GitHub Desktop) и откройте папку в JustAI (📁).
2. ⚙ Настройки → **GitHub**:
   - Токен GitHub, Репозиторий `владелец/имя`;
   - «Брать задачи из GitHub на этом ПК» = `on`;
   - «Кто выполняет задачи» = Ollama (или любой провайдер); профиль `coder`.
3. Сохраните. В блоке «Мост GitHub» появится «ждёт задачи».

Задачи выполняются без присмотра: действия, которые обычно требуют подтверждения (опасные команды), отклоняются — агент ищет другой путь или пишет об этом в отчёте. Если в папке есть ваши незакоммиченные изменения, задачи ждут.

## 3. ПК2 — планировщик

1. Установите JustAI, подключите сильную модель (например, GPT по API: провайдер OpenAI или «Свой сервер»).
2. ⚙ Настройки → **GitHub**: тот же токен и репозиторий, «Брать задачи» = `off`.
3. В чате выберите профиль **Architect** и опишите, что нужно сделать. Архитектор разобьёт работу на задачи, поставит их, проверит pull requests и попросит доработки.

Задачи можно ставить и вручную: создайте issue с меткой `justai` (от владельца токена или логина из списка «Кто может ставить задачи»). Правки — обычным комментарием в issue.

## Если планировщик может только создавать issues

Некоторые интеграции (GitHub App у веб-нейросетей) получают право создавать issues, но не ставить метки и не комментировать — и при этом сообщают об успехе. Тогда:

- **Задача** — issue с `[justai]` в начале заголовка **или** отдельной строкой `/justai` в описании. Метку `justai` мост поставит сам.
- **Доработка** — новый issue, в описании отдельная строка `/justai #3` (номер задачи) и ниже текст правок. Мост применит его как комментарий к #3, ответит в нём и закроет служебный issue.

## Ход работы, остановка и продолжение

- **Ход работы.** В начале задачи JustAI публикует в issue комментарий и обновляет его каждые ~30 с: число шагов, план агента с отметками, последние действия (✓ / ✕ с текстом ошибки) и предупреждение, если одна и та же ошибка повторяется.
- **Остановить.** Комментарий `/justai stop` в issue задачи — или (если планировщик не может комментировать) новый issue со строкой `/justai stop #N`. JustAI прерывает агента в течение ~30 с, сохраняет сделанное в ветке (коммит `JustAI: WIP: …`, push, PR обновляется), пишет, на чём остановился, и ставит метку `justai:paused`.
- **Продолжить.** Когда угодно: комментарий с указаниями в issue — или issue со строкой `/justai continue #N` (или `/justai #N`) и текстом ниже. Агент продолжает **в той же сессии**, с полной историей, с места остановки.
- Если JustAI перезапустили посреди задачи, при следующем запуске она продолжается сама.

## Проверки и тестирование через ПК1

Планировщик не видит экран ПК1, поэтому мост сам присылает факты.

- **Проверки в каждом отчёте.** После задачи JustAI сам (не агент) запускает проверки проекта (`JUSTAI_VERIFY`, по умолчанию typecheck и тесты) на закоммиченном коде. В отчёте: `✅ все прошли` или `❌ не прошли` по каждой команде, у упавших хвост вывода.
- **Задача-проверка** — issue с `[justai-test]` в начале заголовка или строкой `/justai test` в описании (`/justai test #N` — проверить ветку задачи N, то есть её pull request; без номера — основную ветку). Агент-проверяющий (профиль `tester`) **не меняет файлы**: ставит зависимости, запускает тесты и скрипты, поднимает dev-сервер, проходит сценарий в браузере (клики, ввод, текст страницы, ошибки консоли) и снимает скриншоты (в том числе на ширине 375 px). В issue — `✅ PASS` / `❌ FAIL`, отчёт по шагам, проверки проекта и **скриншоты** (они лежат в служебной ветке `justai-artifacts`). Всё, что проверка оставила в папке, после неё удаляется.
  ```
  [justai-test] Проверь главный экран
  1. Открой сайт, нажми каждую из 4 карточек режимов — должна открываться своя страница.
  2. В консоли не должно быть ошибок.
  3. Скриншоты на ширине 1280 и 375.
  /justai test #5
  ```
- **Команда** — комментарий в задаче `/justai run npm test` (выполняется в ветке этой задачи) или issue, первая строка которого `/justai run #N команда` (без `#N` — основная ветка; issue закрывается после ответа). В ответ: код выхода, время и хвост вывода. Разрушительные команды (`git push`, `rm -rf`, реестр, выключение…) отклоняются; предел времени — 5 минут.
- В профиле **Architect** это инструменты `github_test_task` и `github_run_command`; `github_review_task` показывает и результаты команд.

## Метки состояния

| Метка | Значит |
|---|---|
| `justai` | задача для JustAI |
| `justai:working` | ПК1 сейчас её выполняет |
| `justai:review` | готов pull request — проверьте или напишите правки комментарием (у задачи-проверки: PASS) |
| `justai:failed` | не получилось — причина в последнем комментарии (у задачи-проверки: FAIL) |
| `justai:paused` | остановлено командой `/justai stop` — ждёт указаний, чтобы продолжить |

## Безопасность

- Только приватный репозиторий (иначе отказ; обойти — `JUSTAI_GITHUB_ALLOW_PUBLIC=on`, не рекомендуется).
- Задачи и правки принимаются только от владельца токена или логинов из «Кто может ставить задачи». Свои отчёты JustAI помечает скрытой меткой и не принимает за правки.
- Токен передаётся git через переменные окружения — не попадает в адрес репозитория, конфиг git и команды агента.
- `.justai` (сессии, токен JustAI, состояние моста) не коммитится никогда.
